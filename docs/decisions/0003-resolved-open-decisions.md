# 0003: Open decisions from SPEC section 9, as resolved by the implementation

Status: **Accepted**. SPEC.md is not rewritten; this records what was decided and why, with the code or ADR that carries it.

1. **From scratch, or port?** From scratch, in Zig, following published designs (backtracking VM with an explicit stack, Pike VM, lazy DFA with a reverse pass, byte-sequence lowering of Unicode classes). No code is ported, so no third-party licence applies. The only vendored data is the Unicode Character Database (Unicode License), as generated tables (ADR 0001).
2. **Unicode data.** Resolved in ADR 0001: tables generated from the UCD by `tools/gen_unicode.py`, version pinned (18.0.0) and recorded with input checksums in the generated file; optional with `-Dunicode_tables=false`.
3. **Perl subset for `grep -P`.** The Perl dialect is a subset of Perl/PCRE: groups (capturing, named, non-capturing), inline flags `i m s x`, greedy, lazy and possessive quantifiers, atomic groups, look-ahead and fixed-width look-behind, back-references, `\\b \\B \\A \\z \\Z \\G`, `\\Q..\\E`, `\\h`, classes with POSIX names, and `\\p{..}` / Unicode `\\w \\d \\s` with `utf8`. Not supported and reported as errors: recursion, conditionals, subroutine calls, `\\K`, `\\R`, `\\X`, `(*VERB)`s, branch reset, variable-width look-behind. Full PCRE2 compatibility is not a goal, and PCRE2 is not vendored: vendoring a C library would give up the Zig-only build, and the subset above covers what the first consumers need. Revisit if `grep -P` users hit the unsupported list. Per-construct detail: `docs/compatibility/perl.md`.
4. **Multi-pattern strategy.** `RegexSet` combines the patterns into one alternation, so one DFA scan serves all of them (`grep -f` is a single pass). Aho-Corasick and Teddy-style SIMD for large literal sets were not built; measure with a real `grep -f` workload before adding either. `matchedPatterns` reports which patterns match by running each one separately, which is O(patterns).
5. **Captures on the DFA fast path.** No. The DFA gives the span; the Pike VM computes captures on that span only when the pattern has groups (ADR 0002, section 9).
6. **Streaming semantics.** Line-oriented only (`LineStream`, `Searcher.matchingLines`): a pattern is matched against one line at a time, so no match crosses a buffer boundary, the engine needs no look-behind beyond the line, and memory is one line (a longer line than the reader buffer is `StreamTooLong`, never a silent split). Streaming of matches that may span lines (a sliding window over a reader) is not implemented; it would need an incremental Pike VM.
7. **Haystack encoding at comptime or runtime.** Runtime: `Options.utf8` chosen per `Regex`, because a grep must pick it from the locale at startup and a comptime parameter would double the generic surface for little gain.
